# แอปเว็บคำนวณไบอัส DC ของ BJT Common-Emitter — เอกสารออกแบบ

- วันที่: 2026-11-10
- สถานะ: รออนุมัติ
- ขนาดงาน: งานเล็ก (design doc ฉบับย่อ)

## เจตนา

แอป Flask ขนาดเล็กที่ใช้งานได้จริงสำหรับแล็บ ENG29 2121 รับค่าจากฟอร์มและ
คำนวณจุดทำงาน DC (DC operating point) ของทรานซิสเตอร์ NPN แบบ
common-emitter ที่ไบอัสด้วยวงจรแบ่งแรงดัน แสดงผลพร้อมหน่วย ตรวจสอบข้อมูล
นำเข้า และเตือนเมื่อทรานซิสเตอร์ไม่ได้อยู่ในช่วง active พร้อมตรวจทานผลด้วย
การคำนวณอีกวิธีที่เป็นอิสระจากกัน นักศึกษาเปิดใช้บน localhost เพื่อเรียนรู้
และตรวจสอบคำตอบ

## เป้าหมาย

- รับค่า VCC, R1, R2, RC, RE, beta, VBE ผ่านฟอร์มเว็บ
- แสดง VB, VE, VC, VCE, IB, IC, IE พร้อมหน่วย
- ตรวจสอบทุกค่า และแสดงข้อผิดพลาดรายช่องเป็นภาษาไทย
- ตรวจจับและเตือนภาวะ cutoff และ saturation
- แสดงผลจากวิธี analytic และวิธี numeric อิสระเคียงกัน พร้อมผลต่างและ
  สถานะผ่าน/ไม่ผ่าน
- แยกไฟล์ engineering logic, routes, templates, CSS และ tests ออกจากกัน
- รันบนเครื่องด้วยคำสั่งเดียว และ commit/push ให้เสร็จวันนี้

3. **เครื่องคิดเลขฝั่ง browser ด้วย JavaScript**
   ไม่เลือก: โจทย์กำหนดให้เป็นแอป Flask ที่มี Python logic และ test ฝั่ง
   server แยกออกมา

สำหรับการคำนวณอิสระ:

- **A. ใช้ analytic อย่างเดียว แล้วตรวจด้วยค่ามือใน test**

### สมการหลัก (analytic)

สมมูล Thevenin ของวงจรแบ่งแรงดันที่เบส:

```
VBB = VCC * R2 / (R1 + R2)
RB  = R1 * R2 / (R1 + R2)
IB  = (VBB - VBE) / (RB + (beta + 1) * RE)
IC  = beta * IB
IE  = (beta + 1) * IB
VE  = IE * RE
VB  = VE + VBE
VC  = VCC - IC * RC
VCE = VC - VE
```

ถ้า `VBB <= VBE` แปลว่าไบอัสเบส-อีมิเตอร์ยังไม่ forward: รายงานเป็น cutoff
โดย `IB = IC = IE = 0`, `VE = 0`, `VC = VCC`, `VB = VBB`, `VCE = VCC`

### วิธีอิสระ (numeric cross-check)

แก้ circuit เดียวกันเป็นระบบสมการเชิงเส้น 3 node โดยไม่ใช้การยุบเป็น
Thevenin ตัวแปรคือ `VB, VE, VC`:

```
KCL ที่เบส:      VB*(1/R1 + 1/R2) + VE/((beta+1)*RE) = VCC/R1
ความสัมพันธ์:    VB - VE = VBE
KCL ที่คอลเลกเตอร์: VC/RC + beta*VE/((beta+1)*RE) = VCC/RC
```

แก้ด้วย Gaussian elimination และ partial pivoting ใน pure Python แล้วคำนวณ
`IB, IC, IE` จาก `VE` ถ้าผลลัพธ์ได้ `IB <= 0` ให้ใช้ผล cutoff แบบเดียวกับ
analytic จากนั้นเปรียบเทียบทีละค่า ด้วย
`math.isclose(rel_tol=1e-9, abs_tol=1e-9)` หน้าเว็บแสดงผลต่างสัมบูรณ์ที่มาก
ที่สุดและสถานะผ่าน/ไม่ผ่าน

### การตรวจสอบข้อมูล

ตรวจฝั่ง server ทุกช่องต้องมีค่าและแปลงเป็น float ที่ finite ได้:

- `VCC > 0`
- `R1 > 0`, `R2 > 0`, `RC > 0`, `RE > 0`
- `beta >= 1`
- `0 < VBE < VCC`

ถ้าไม่ผ่าน ให้แสดงฟอร์มเดิมพร้อมค่าที่กรอก ข้อความภาษาไทยข้างช่องที่ผิด
และ HTTP 400 โดยไม่คำนวณผล

### การตัดสินช่วงการทำงาน

- **Cutoff:** `VBB <= VBE`
- **Saturation:** `VCE < 0.2 V` (ค่าคงที่ `VCE_SAT_V = 0.2`) พร้อมเตือนว่า
  สมการช่วง active ใช้ไม่ได้แล้ว และ VCE จริงใกล้ศูนย์
- **Active:** กรณีนอกเหนือจากนั้น แสดงเป็นปกติ

### Routes และหน้าเว็บ

- `GET /` — ฟอร์ม 7 ช่อง พร้อมค่าตัวอย่างที่ทำงานได้ทันที
  (`12, 47000, 10000, 2200, 1000, 150, 0.7`)
- `POST /calculate` — ตรวจสอบ คำนวณทั้งสองวิธี แล้วแสดงหน้าผลลัพธ์
- หน้าผลลัพธ์: สรุปค่าที่กรอก, ตาราง operating point, ป้ายช่วงการทำงาน,
  คำเตือน, ตารางเปรียบเทียบ (ค่า, analytic, independent, delta),
  ป้ายผ่าน/ไม่ผ่าน และลิงก์กลับไปฟอร์ม
- ป้ายและคำอธิบายเป็นภาษาไทย ศัพท์วิศวกรรมและหน่วยเป็นภาษาอังกฤษ
- CSS ธรรมดา: ตารางอ่านง่าย สีเตือนชัดเจน ไม่ใช้ framework หรือ JavaScript

### การทดสอบ

- ตัวอย่าง active ที่รู้คำตอบ: ตรวจ VB, VE, VC, VCE, IB, IC, IE ถึง 6 ตำแหน่ง
- ตัวอย่าง saturation: มีคำเตือน และรายงานช่วงเป็น saturation
- ตัวอย่าง cutoff: กระแสเป็นศูนย์, VCE = VCC, รายงานช่วงเป็น cutoff
- Validation: หนึ่ง test ต่อหนึ่งกฎ พร้อมกรณีไม่ใช่ตัวเลขและช่องว่าง
- Cross-check: analytic กับ numeric ตรงกันทั้งกรณี active, saturation, cutoff
- Routes: `GET /` ได้ 200 ครบทุกช่อง; `POST /calculate` ที่ถูกต้องได้ 200
  พร้อมค่าและหน่วย; POST ที่ผิดได้ 400 พร้อมข้อความไทยและคงค่าที่กรอก
